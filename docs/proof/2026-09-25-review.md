# Proof run: plain vs lean agents on one review workflow (2026-09-25)

**Short version:** on this workflow, in this setup, the lean roles read 83% fewer tokens per run and found the same 6 of 6 planted bugs. They were also about 16% slower per run. Two plain runs differed from each other by 1% in tokens read, so the token gap is far bigger than the noise. The time gap is not.

## Setup

- **CLI:** `claude --version` → `2.1.282 (Claude Code)`. Claude Code on the web (cloud session).
- **Model:** `claude-opus-5-5` for all 64 turns (X-ray "Models" table).
- **What a default agent loads here** (first-turn makeup): 225 deferred tools (5.7k tokens) and 29 skills (4.1k tokens), plus about 36.6k of tool definitions and other context that isn't in the log. Median first turn: 47.9k. Most deferred tools come from the connected MCP servers (calendar, mail, Trello, Shopify, Figma, docs, GitHub, session tools). The counts come from the `deferred_tools_delta` and `skill_listing` attachments in a plain agent's transcript. The lean agents have neither listing.
- **Roles:** the project copies in `.claude/agents/` (`rolePrefix: ""`), because cloud sessions don't load the repo's plugin marketplace. A one-line `judge` call and the roles check (`2026-09-25-roles-check.md`) showed that all five roles loaded, each with only its listed tools (plus `StructuredOutput`). Each role started at 6.0k tokens or less, against 47.1k for a default agent.
- **Workflow:** `proof/review.workflow.js`, 7 agents (3 reviewers → 3 checkers → 1 judge), run in the order plain, lean, plain, lean, one at a time, in the same session.

- **Tokens read** is the solid result. The two lean runs read 140.0k and 140.2k, the two plain runs 810.6k and 816.6k. The gap is about 80 times the noise.
- **Cost** is noisier. Two identical plain runs differed by 23%, because the split between cache writes and cache reads changed between them. The -62% is well outside that, but treat the exact figure loosely.
- **Time: lean did worse.** Lean runs took 50.2 s and 52.2 s, plain runs 43.8 s and 44.9 s. That's about 16% slower, more than the 3% gap between the plain runs, and it held in both pairs. Two runs each is too few to call this settled, and this data doesn't show why. One visible difference is that lean reviewers took a median of 3 turns, against 2 for plain agents (X-ray "Fixed start by agent type"). The total was 16 turns per run either way.
- Lean agents also wrote about 8% more output tokens, a small absolute difference (4.4k vs 4.8k per run).

## Errors and answer key

- Unknown-tool errors: 0 in every run. The lean roles never tried to call a tool they don't have.
- Answer key: `score.js` found no run whose agents touched `proof/grading/`.
- All 28 agents across the four runs finished: no errors, no empty results.

## Limits

- One workflow, one small target with six easy-to-spot planted bugs, two runs per variant. This is not a statistical proof.
- Quality didn't separate the variants: both scored 6/6 every time. A harder target might show a difference either way.
- The size of the saving depends on this setup. This cloud session has many connectors (225 deferred tools) and 29 skills, which is what makes default agents heavy. A setup with fewer connectors and skills would save less.
- The runs happened in the same session on the same day, alternating, but prompt caching can still carry over between runs (see the cache-write swing in the noise floor).
- The roles were the project copies in `.claude/agents/`, not the installed plugin. A test keeps them identical.
- Only one model (`claude-opus-5-5`) and one CLI version (2.1.282).

The claim is: **on this workflow, with this setup,** the lean roles cut tokens read by about 83% with no loss in bugs found, and ran about 16% slower.
